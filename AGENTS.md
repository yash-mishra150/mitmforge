# AGENTS.md — MitmForge

## What this is

Native HTTP/HTTPS MITM debugging proxy (Proxyman/Charles alternative), built with Tauri 2 + React 19 + TypeScript + Rust. Phase 2 done: `src-tauri/src/proxy.rs` runs a hudsucker 0.25 MITM engine (in-memory CA, HTTP/1.1, sequential-exchange correlation only) streaming `ProxyEvent`s to the React traffic grid. Full product spec: `docs/next_gen_proxy_brd.md` (breakpoints, map local/remote, OpenRouter AI) — it predates the code; where they disagree, the code is newer.

## Commands

```sh
npm run tauri dev      # dev app: Vite on 1420 (strict) + Rust, hot reload both sides
npm run tauri build    # typecheck (tsc) + vite build + Rust release bundle
npm run gen:bindings   # regenerates src/bindings.ts (cargo test --test export_bindings)
npx tsc --noEmit       # frontend typecheck only
cargo test             # inside src-tauri/ — includes the engine e2e test (proxy on 127.0.0.1:18080)
cargo clippy --all-targets -- -D warnings   # inside src-tauri/
```

- `npm run build` (plain vite build) is **not** the app build — use `npm run tauri build`.
- No CI configured yet.
- Toolchain: Node 20+, Rust with edition-2024 support (1.85+). Windows needs MSVC + WebView2.

## Architecture (OpenIDEA-style, single crate)

- `src-tauri/src/proxy.rs` — the engine. **Tauri-free**: emits `ProxyEvent`s through a `Sink = Arc<dyn Fn(ProxyEvent)>`; testable headless (`tests/proxy_engine.rs`). HTTP/1.1 sequential only — `http2` feature would need different correlation plumbing.
- `src-tauri/src/commands/` — thin typed IPC adapters (`#[tauri::command] #[specta::specta]`), registered in `commands/mod.rs::builder()`. **Do not put a command in the same module as its `collect_commands!` reference** — the macro re-imports the command's generated macros into the calling module and collides (E0255).
- `src/bindings.ts` — generated by tauri-specta (`npm run gen:bindings`); never hand-edit; commit after IPC type changes. `specta` u64 fields need `dangerously_cast_bigints_to_number()` (already set).
- Events: single backend→UI channel `proxy://event`, payload is the tagged `ProxyEvent` enum; frontend narrows on `payload.type` (OpenIDEA `ide://event` pattern). High-volume binary data will use `tauri::ipc::Channel<T>`, not this bus.
- Frontend: `src/features/<name>/` feature folders with zustand stores; traffic grid virtualized via `@tanstack/react-virtual`; Tailwind **v4** (vite plugin + `@import "tailwindcss"`, no tailwind.config).
- Proxy starts from the frontend (`commands.proxyStart()` **after** the listener attaches) so early traffic isn't lost. shortcut: engine death requires app relaunch (STARTED never resets); lifecycle commands come later.

## Windows gotchas

- `src-tauri/build.rs` links `windows-app-manifest.xml` (comctl32 v6) into **every** binary of the package. Without it, test executables die at load with `STATUS_ENTRYPOINT_NOT_FOUND` (comctl32 v6-only exports like `TaskDialogIndirect`). Same fix OpenIDEA uses.
- `src-tauri/src/main.rs` has `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` — do not remove.
- Crate is `mitmforge_lib` (lib/bin name collision on Windows) — do not rename.
